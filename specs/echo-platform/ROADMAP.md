# JP Echo: reading, capture, and native apps

**Decision report · 7 November 2026 · Planned, not shipped**

Echo should let people read real Japanese, look up a word without leaving the page, and keep the word or sentence for later practice. We will build a Chromium extension in [WebMods](https://github.com/KakkoiDev/webmods) and package Echo as iOS and Android apps with [Capacitor](https://capacitorjs.com/). The web app remains available. Native releases should include local reminders, screen-locked audio, device storage, and an update mechanism from the first release.

## What we learned from Sluka

[Sluka](https://sluka.app/#how) presents lookup and vocabulary grading as part of reading. An unfamiliar word stands out, its meaning is one action away, and a learner’s decision follows that word to the next page. Sluka describes this as a way to get more real reading and listening without a separate review queue. These are product observations from its public description, not a benchmark of Japanese lookup quality.

Echo should adopt that low-friction reading loop while keeping its own strength: turn chosen material into shadowing, recall, and sentence review. Reading and dictionary lookup should work without AI. Ask AI only when the learner requests help with a translation, a reading, or shorter practice examples. Keep manual word recognition separate from automatic encounters and sentence review progress. A word appearing in an imported sentence does not mean the learner knows it.

## Chromium extension: Echo Reader

**Decision:** Ship a Manifest V3 companion in WebMods. Use the existing [Echo Reader specification](../echo-reader/SPEC.md) as the engineering starting point. That draft proposed a userscript first and deferred an extension; this roadmap makes the Chromium extension a delivery requirement. Its detailed sync proposal is a candidate, not a commitment to edit a full backup from a browser tab.

1. **Look up in place.** Follow [Yomitan’s interaction model](https://github.com/yomidevs/yomitan#what-is-yomitan): hold a configurable key and point at Japanese text, or select a phrase, to open a popup with reading, meanings and a matched span. Support keyboard navigation and a touch-friendly action where possible. Use JP Core’s matcher and dictionary, with longest-match ranking, conjugation handling and part-of-speech checks. Keep dictionary attribution and distribution terms with the packaged data. Yomitan is a UX reference; do not copy its code or rules into this build.
2. **Save word and save sentence independently.** Save a dictionary entry with its surface form and optional context, or save the complete original sentence around the cursor. Show the exact sentence before saving and let the learner fix boundaries around quotes, lists and fragments. A word can be saved without creating a sentence card. A saved sentence can enter Echo with translation or readings pending; capture should not depend on a provider key or successful AI response. Echo can later generate shorter examples that stay in the original situation, one focus word per example. Save page title or URL only if enabled.
3. **Connect to Echo without assuming shared storage.** Store an offline outbox in the extension. Deliver versioned word and sentence records to the paired Echo web app, initially through an explicit handoff to Echo’s own origin, with a JSON export/import fallback. The extension cannot write into another origin’s IndexedDB directly. Echo validates and deduplicates captures using stable entry and capture identities, acknowledges only after persistence, and never resets existing review history. Label queued and saved states separately. Test replay after closing the browser, retries, and duplicate captures. For cross-device delivery to native Echo, start with deck transfer or an opt-in sync channel; evaluate the existing gist setup only after testing simultaneous saves and backup writes.
4. **Fit WebMods.** Follow its [companion extension guide](https://github.com/KakkoiDev/webmods/blob/HEAD/docs/EXTENSIONS.md): keep the reader userscript as source, generate the Chromium content script with its build tool, and hand-author the manifest and extension-only bridge as needed. Run DOM lookup in an isolated world. Bundle executable code; no remote scripts in the store build under [Chrome’s Manifest V3 rules](https://developer.chrome.com/docs/extensions/develop/migrate/remote-hosted-code). Request per-site access where feasible and keep credentials and the save queue out of arbitrary page scripts.
5. **Add persistent word states next.** Let readers mark words Learning, Known or Ignore; let Echo reflect those choices across texts. Make highlights opt-in per site, with lookup usable on its own. Captions, richer dictionary packs and broad highlighting are follow-ups after ordinary web-page capture works.

**First acceptance test:** On an ordinary Japanese web page, look up an inflected verb, save the word and its containing sentence independently, go offline, reconnect, and find both in Echo exactly once. Verify that capture and lookup did not contact an AI service, and that an existing card’s review state was preserved.

## iOS and Android: Capacitor shell

Keep one Echo UI and one set of sentence, review, dictionary and backup rules. Bundle the web assets inside each native binary for offline startup. Add a small native adapter for the capabilities below; keep the current browser implementations for the PWA. Do not register the PWA service worker inside the native shell or make the native app load the live production URL as its application bundle.

| Built into the first native release | Implementation and boundary |
| --- | --- |
| **Local notifications** | Use [Capacitor Local Notifications](https://github.com/ionic-team/capacitor-local-notifications) for opt-in review reminders that the OS schedules. Reconcile schedules when settings or review state changes and on launch; a tap opens Review. Request permission when the learner enables reminders. Use inexact scheduling where the OS requires it. Local reminders need no push server; remote push is a separate feature. |
| **Audio with the screen locked** | The current Radio path uses web speech and a screen wake lock. Native mode needs an OS-owned playback queue. Prototype [iOS playback audio session](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/playback) with the background audio mode, and [Android Media3 MediaSessionService](https://developer.android.com/media/media3/session/background-playback) with the media-playback foreground service. Hand off cached audio clips or rendered on-device TTS to the player before lock. Native code owns queue timing and playback controls, including Radio’s phase transitions; do not rely on WebView timers while locked. Test interruption, audio routing, pause and stop. Background playback continues a session the learner started; it does not bypass force-quit, system restrictions, or permission settings. |
| **Device storage** | Use [Capacitor Filesystem](https://github.com/ionic-team/capacitor-filesystem) for private book files, audio caches and backup exports. Use a native database adapter (SQLite is the leading option) for transactional library and review records if the device spike confirms migration and restore. Use native settings for small preferences and platform secure storage for credentials. Browser IndexedDB stays on the web. PWA data does not automatically appear in the native sandbox; reuse the versioned Echo backup format for migration and verify round-trip fidelity before offering to switch. |
| **Over-the-air updates** | Build in a compatible-bundle updater from day one; evaluate [Capacitor Updater](https://github.com/Cap-go/capacitor-updater) before writing one. Publish permitted updates on demand, check on launch/resume and via **Check for updates**, stage signed bundles with checksums and supported native build ranges, and activate only at an idle boundary. Keep the embedded bundle and last working bundle for offline startup and rollback. Never interrupt a review, recording or audio session to activate an update. |

### What “OTA anytime” means

We want to be able to **publish** an eligible update whenever it is ready. We cannot guarantee an immediate update on an offline, locked or suspended phone, nor bypass store review. Native binaries, plugins, capabilities and permissions ship through normal releases. Use store distribution for feature changes unless the applicable rules clearly allow another route. In particular, [Apple App Review Guideline 2.5.2](https://developer.apple.com/app-store/review/guidelines/#software-requirements) restricts downloaded code that introduces or changes app functionality. Review [Google Play’s device and network abuse policy](https://support.google.com/googleplay/android-developer/answer/9888379) before enabling executable-bundle updates on Play builds. Do not infer permission from an updater vendor’s feature list.

Use separate internal, beta and store release channels. Start public builds with bundled code and compatible content updates; enable live web bundles only on channels where the distribution rules allow that use. Keep a store-release fallback. Verify signatures before activation, mark the bundle healthy only after startup and database checks, and test rollback against interrupted downloads, old native bridges and storage migrations. Bundle rollback must not erase learner data. Extension code releases remain separate and follow the Chrome Web Store update path.

## Order of work

| Milestone | Exit condition |
| --- | --- |
| **1. Read and capture** | Shared lookup works in Echo and a WebMods unpacked Chromium build. Word and sentence capture reach Echo offline-first without duplicate saves. |
| **2. Native capability spike** | On a real iPhone and Android device: install a bundled build, schedule a local notification, play an Echo loop and Radio queue with the screen locked, and export/restore a library. Confirm platform permissions and audio behavior before selecting plugins. This can proceed independently of the extension. |
| **3. Native release foundation** | The PWA and both native builds pass the same library/review checks. Lock-screen controls, migrations, notification permission-denied behavior, and a permitted OTA/rollback exercise pass on devices. |
| **4. Extend immersion** | Add local EPUB/pasted-text highlighting, cross-device vocabulary state and optional caption support based on use. Only then broaden background capture or sync. |

Keep release scope small: prove lookup → capture → practice and locked-screen playback before investing in broad site coverage, cloud sync, or a second UI.
