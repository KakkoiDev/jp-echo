# Quick round: audit pack

Everything the N2 game in Echo asks, or plans to ask, laid out as plain files
so other reviewers (people or AIs) can check it without running the app.

- **CONCEPT.md**: what the game is for and the principles it must keep.
- **RULES.md**: exactly how it plays: question kinds, timing, points, which
  questions come up, what is saved.
- **SUMMARY.md**: counts, generated with the data.
- **questions/**: every question the game can ask today, one JSON object per
  line, per kind, as the game builds it.
- **data/**: the source lists behind them: vocabulary, readings, grammar,
  kanji, connectives, connective passages and the authored exam questions.

`questions/` and `data/` are generated by `node tools/build-game-audit.mjs`
from the code the game runs (`n2-game.js`). Don't edit them by hand: fix the
source, then rebuild.

## How to audit

Please report each problem with its **id** (questions) or **row** (data
files), what is wrong, and what it should be. A problem in a generator (one
rule producing many bad questions) is worth more than a single bad item, so
say when you see a pattern.

### 1. Correctness of the Japanese

- **data/vocabulary.tsv**: is the reading right? Is "meaning (as shown)" a
  fair short English meaning? Is the sentence natural N2-level Japanese, are
  its readings (in 【】 after each word) right, and does the translation match?
- **data/grammar.tsv**: is the meaning right for the pattern, and does the
  sentence use the pattern naturally and correctly?
- **data/kanji.tsv**: readings come from KANJIDIC2; check the word list
  against them only if something looks off.
- **data/exam-questions.tsv**: is the marked answer the only correct one? Is
  the explanation ("why") right? These were written for Echo and have not had
  a native review yet.

### 2. Are the wrong choices really wrong?

The most important check. A wrong choice that is also correct makes the game
teach the wrong thing.

- **questions/reading.jsonl**: `wrongCandidates` are near misses made by
  changing one sound (voicing, vowel length, small っ, small ゃゅょ). Is any of
  them also a correct reading of the word (for example a word with two
  accepted readings)?
- **questions/meaning.jsonl** and **listen.jsonl**: is any wrong meaning also
  a fair meaning of the word?
- **questions/definition.jsonl**: could any wrong word also fit the
  definition?
- **questions/homophone.jsonl**: in the sentence, could a wrong word also be
  correct?
- **questions/grammar.jsonl**: is any wrong meaning also a fair meaning of the
  pattern?

### 3. Is it good for the exam?

- Do the question kinds match what JLPT N2 tests (問題1 漢字読み, 問題2 表記,
  問題3 語形成, 問題4 文脈規定, 問題5 言い換え, 問題7 文法形式, the reading
  section)? What is missing or over-weighted?
- Are the time limits (RULES.md) realistic for N2 pace?
- **data/connectives.tsv**: is each connective's job right? Which important
  N2 connectives are missing?
- **questions/connective.jsonl** (問題9 style): in each excerpt, is the
  answer the only connective that fits, and could any wrong choice also fit?
  The wrong choices skip jobs listed as overlapping in `OVERLAP`
  (n2-connectives.js); say if a pair should be added.
- **data/connective-passages.tsv**: for the planned connective cards, is the
  blanked connective the only good fit given the sentence before? Mark rows
  where two connectives would fit.

### 4. The rules

Read RULES.md as a game designer and a learning scientist:

- Does the scoring ever reward guessing over "I don't know"?
- Does the repetition (misses come back next round; weak items first) give
  enough exposures for something seen "hundreds of times" to stick, without
  wasting time on items already known?
- Anything that would make a tired learner stop playing?

## What is not built yet

- **Kanji from parts**: a compound the learner hasn't studied, its reading or
  meaning worked out from what its kanji usually do (data/kanji.tsv).
- **Grammar from parts**: a pattern shown as its building blocks
  (ざる + を + 得ない). The block table isn't written yet.
